# Realty 2.1.0

Another plugin can now run auctions and offers through the Realty API. It gets the same events and notices as the in-game commands, and it can list what is open after a restart. Handing a role to the player who already holds it is now refused.

## Upgrade

Replace the Realty plugin jar. The database schema is unchanged, so `realty-rest` and the modules can stay on 2.0.

## Changes in behaviour

- **`/realty offer toggle` says when nothing changes.** Turning offers on for a freehold that already accepts them, or off when it already refuses them, now answers "already". It no longer reports a change. The new message is `toggle-offers.no-change` in `messages.yml`.
- **A console cancel fires an event.** `AuctionCancelledEvent` now fires when the console cancels an auction, with no actor.

- **Giving a role to its current holder is refused.** `/realty transfer`, `/realty set titleholder`, `/realty set tenant` and `/realty set landlord` now refuse a player who already holds that role. `/realty unset titleholder` and `/realty unset tenant` refuse when nobody holds it. Before, each wrote a history entry, fired a change event and cleared the region's WorldGuard members. The new messages in `messages.yml` are `transfer.already-titleholder`, `set-titleholder.already-titleholder`, `set-tenant.already-tenant`, `set-landlord.already-landlord`, `unset-titleholder.no-titleholder` and `unset-tenant.no-tenant`.

## For plugin developers

This covers `realty-paper-api` and `realty-backend-api`.

### Events now fire from the API

`RealtyPaperApi` fires the auction and offer events itself, so the events and notices are the same whether a command or a plugin acted. The commands no longer fire their own.

| Method | Fires first, and can be cancelled | Fires once done |
|---|---|---|
| `createAuction` | `AuctionCreateEvent` | `AuctionCreatedEvent` |
| `performBid` | `AuctionBidEvent` | `AuctionBidPlacedEvent` |
| `cancelAuction` | | `AuctionCancelledEvent` |
| `payBid`, when paid in full | | `AuctionWonPurchaseEvent` |
| `placeOffer` | `OfferPlaceEvent` | `OfferPlacedEvent` |
| `acceptOffer` | `OfferAcceptEvent` | `OfferAcceptedEvent` |
| `withdrawOffer` | | `OfferWithdrawnEvent` |
| `rejectOffer`, `rejectAllOffers` | | `OfferRejectedEvent`, one per offer |
| `toggleOffers`, on a change | | `OffersToggledEvent` (new) |
| `payOffer`, when paid in full | | `OfferPurchaseCompletedEvent` |

- **A vetoed action returns `Cancelled`.** When a listener cancels a pre-event, the method returns a new `Cancelled` result: `CreateAuctionResult`, `BidResult`, `OfferResult` and `AcceptOfferResult` each have one. Before, the API ignored the veto, because it fired no pre-event at all.
- **A no-op toggle returns `NoChange`.** `toggleOffers` returns `ToggleOffersResult.NoChange` when the freehold is already in the requested state, and fires no event.
- **An unchanged role returns `NoChange`.** `SetTitleHolderResult`, `SetTenantResult` and `SetLandlordResult` each gain a `NoChange` variant, in `RealtyPaperApi` and in `RealtyBackend`. It is returned when the new holder already holds the role, or when clearing a role nobody holds, and no event fires.
- **An exhaustive `switch` over these results must handle the new variants.** Code compiled against 2.0 throws `MatchException` when it meets one.
- **The pre-events fire on the main thread.** A call from another thread waits one tick for them.

### New and changed events

- **`AuctionCreatedEvent`** gains `getBiddingDurationSeconds()`, `getPaymentDurationSeconds()` and `getBiddingEndsAt()`.
- **`AuctionBidPlacedEvent`** gains `getPreviousBidderId()`, which is empty on the first bid, and `getBiddingEndsAt()`.
- **`AuctionCancelledEvent`** gains `getBidderIds()`. `getActorId()` now returns an `Optional<UUID>`, which is empty when the console or a plugin cancelled.
- **`OfferRejectedEvent.getRejecterId()`** now returns an `Optional<UUID>`, on the same rule.
- **Code that calls `getActorId()` or `getRejecterId()` must be updated and rebuilt.** Code compiled against 2.0 fails with `NoSuchMethodError`, because the return type changed.
- **`OffersToggledEvent`** is new. It fires when a freehold starts or stops accepting offers.
- **`AuctionPaymentExpiredEvent` and `OfferPaymentExpiredEvent`** are new. They fire when a buyer misses the payment deadline, and carry the refund.
  - They extend `PaymentExpiredEvent`, which is not a `RealtyRegionEvent`, because the region may have been deleted by then.
  - `getRegion()` and `getWorldId()` return an `Optional`, which is empty when the region is gone.
- **The constructors of the changed events take the new fields.** A plugin that builds these events itself must pass them.

### New and deprecated methods

- **`listActiveAuctions()`** returns every unfinished auction as a `RealtyBackend.ActiveAuction`. Each has its phase (`BIDDING` or `AWAITING_PAYMENT`), the standing bid, when bidding ends, the payment deadline and the amount paid.
- **`listOfferListings()`** returns every freehold that accepts offers, or is still being paid for through one, as a `RealtyBackend.OfferListing` with its open offers.
- **`cancelAuction(regionId, worldId, actorId)`** names who cancelled. The two-argument form is deprecated and cancels as the console.
